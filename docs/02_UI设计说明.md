## 零、本轮交付的功能清单（全部完成并有回归测试）

| 功能 | 实现方式 | 关键点 / 实测 |
|---|---|---|
| **拖拽导入** | 自建 `ui_dnd.py`（ctypes + `WM_DROPFILES`），**不引入第三方包** | 需要子类化窗口过程；回调必须常驻引用，否则 Windows 调用时崩溃；拖入 `CustomLevels` 根目录会自动展开成歌曲列表，拖入单个文件会取父目录 |
| **多选 + 批量操作** | Treeview 改 `selectmode="extended"`，选择集改为 `set[str]` | 标题徽标显示"已选 N"；`Ctrl+A` 全选当前页、`Esc` 清空；选中 >1 首时 Delete/右键删除自动走**批量删除**（一次确认、逐首执行、失败逐条列出） |
| **对比结果可视化** | `_estimate_copy()` 估算总大小 + 预计耗时 | 复制确认框里显示"总大小 / 预计耗时 / 目标可用空间"，空间不足会给出 ⚠️ 提示 |
| **增量对比** | 载入时先用 `(folder_name, mtime)` 查缓存，只解析新歌与改动过的歌 | 日志会打印"缓存命中 N 首，需重新解析 M 首"；MTP 取不到 mtime 时自动退回全量 |
| **封面墙视图** | 自建 `ui_coverwall.py`（Canvas + 网格），`ttk.Treeview` 做不到图片缩略图 | **虚拟化渲染**：只创建可见范围 ±1 行的格子（40 首只建 25 格）；封面读取走线程池 + 队列；首屏 852 ms（第一版每格 6 个控件要 1.7 s，减到每格 3 个控件后接近减半） |
| **列宽可拖拽 + 记忆** | 三列 `stretch=False`（否则拖不动），松手后回调主程序写入 `settings.json` | 列宽随设置往返，非法值会被清洗；`get/set_column_widths()` 已在测试中覆盖 |
| **表格行 hover** | `<Motion>` 换 tag | 优先级刻意设计为 **高亮 > 选中 > 悬停 > 斑马纹** —— 否则鼠标一划过就看不见哪些是缺失歌曲 |
| **封面圆角 + 阴影** | PIL 预生成圆角遮罩 + 高斯模糊阴影，合成到面板底色 | 结果进缓存复用，不影响切歌流畅度 |
| **CopyHere 弹窗修复** | 标志位改 1556 + `-Replace` 改名挪开 | 详见 `Quest3文件夹选不了_解决方案.md` 第五节 |

**未做的一项**：`PanedWindow` 可拖动分割（三个列表 ↔ 详情栏）。目前改成"详情栏固定宽 + 窗口过窄自动收起 + `Ctrl+D` 手动折叠"，功能上已覆盖"我想让列表更宽"的需求；如果你更希望用鼠标拖分割条，说一声我再换。

高 DPI 适配（`set_widget_scaling`）也没有加：本机是 100% 缩放，无法验证 125%/150% 下的实际效果，
贸然设置缩放可能让原本正常的机器变差 —— 留到有缩放环境时再做。

## 一、修掉三个真实缺陷（靠截图 / 量几何发现，不是靠"看着别扭"）

| 问题 | 现象 | 根因 | 修法 |
|---|---|---|---|
| 窗口被内容撑爆 | 1500px 宽的窗口里，右侧详情栏被挤到只剩 68px 宽，内容被裁掉约 400px | 三个列表各自最小请求宽度 471px，加上详情栏 396px，整窗最小需求 **1885px**；`grid` 会把子控件裁到列宽而不报错 | 压缩列表内部尺寸、右栏显式限宽 `grid_propagate(False)`、窗口尺寸按屏幕夹取，并加"窗口过窄自动收起详情栏" |
| 表格压住翻页条 | 列表底部滚动条与翻页按钮重叠 269px | `_tree` 与 `_pager` **都写在 `grid(row=4)`**；Treeview 的 `height=12` 让请求高度超出可用空间 | Treeview 改 `height=1`（请求最小、由行权重拉伸）；翻页条挪到 `row=4`、表格在 `row=3` |
| 标题栏黑块 | 深色切浅色后，三个列表标题位置各出现一块深色矩形 | ctk 的 `CTkFrame(fg_color="transparent")` 会把主题里 `CTkFrame` 的默认底色（`#3a3a3a`）画上去，外观切换后不会重算 | 容器不再用 `"transparent"`，显式给 `BG_CARD`；并在主题切换后强制整窗重画兜底 |

## 二、设计令牌层（`theme.py`）

之前颜色是散落的十六进制字面量（同一个蓝色在 6 处各写一遍，浅/深色值没有统一管理）。现在：

* **语义色板**：`BG_APP / BG_CARD / BG_ELEVATED / BG_INPUT / BG_HOVER / BG_SELECTED / BG_ZEBRA`、
  `TEXT_PRIMARY / SECONDARY / MUTED / ON_ACCENT`、`ACCENT / SUCCESS / WARNING / DANGER / INFO / NEUTRAL`，
  浅色深色各一套，控件只引用**语义名**；
* **8pt 间距体系** `SPACE`、**圆角阶梯** `RADIUS`、**字号阶梯** `FONT`、**尺寸** `SIZE`；
* `T[...]` 直接给出 ctk 需要的 `(浅色, 深色)` 元组，控件自动跟随主题。

`app.py` / `ui_songlist.py` / `ui_dialogs.py` / `ui_devicepicker.py` / `ui_coverwall.py` 全部在这套令牌上，
旧 `COLOR_*` 常量已无任何引用。
