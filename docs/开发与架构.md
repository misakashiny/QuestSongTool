## 运行数据

Qt 默认运行目录为系统 GenericDataLocation 下的 `QuestSongCompare-QtPreview`。`--data-dir` 也会在指定目录下附加这个独立子目录；代码使用 `QLockFile` 防止两个程序实例同时写同一运行数据。该程序锁与 AI 开发协作限制无关，本轮保留。

主要文件为 `preview.log`、`qt-workspace.json`、`qt-library-ui.json`、`qt-library-userdata.sqlite3`、`qt-downloads.json`、筛选预设、歌单快照和 `transfers/` 事务记录。封面磁盘缓存为 `qt-cover-cache-v1/`。具体文件名以各存储类源码为准。

根目录 `settings.json`、`songs_cache.db`、`downloads.json`、`logs/`、`mtp_mirror/` 属于旧路径运行数据；`qi_reports/` 是控件查看工具报告。本次均保持原位，没有把它们当作文档归档删除。

## 保留下来的重要技术结论

1. GUI 更新由主线程处理。旧 Tk 工作线程通过 TaskRunner 消息返回，直接从后台调用 `root.after` 曾出现异常；Qt 使用信号/槽和主线程事件泵。
2. miniaudio 回调不能在自身回调线程中调用 `device.stop`。切歌、取消和关闭需按当前生命周期处理；静态检查不能验证现场声音和原生拖动。
3. Qt 主题使用共享令牌，双语文案走 `messages.py` / `tr`。封面网格使用模型/委托，避免逐曲建立大量控件或增加循环 Canvas 重绘。
4. 传输仍由原队列和后端实施：明确方向与选曲、设备身份和规范根、完整快照、内容校验、暂存发布及事务记录。默认已有歌曲跳过；确认前目标变化会阻止启动。
5. 传输预览只估算本地文件属性，最多 100000 文件、2 GiB；不读取设备，也不作为完整性、覆盖或缺失判断依据。结果分类和失败重试复用原队列。
6. 设备元数据先返回，封面/缺失时长仅对可见项与选中项按每批最多4首补全；共享 provider I/O 锁，设备/根/代次变化时丢弃迟到结果。
7. 时长通过有界音频头尾解析，单曲大小/头部/尾部已合并一次 ADB 读取；未知时长不伪造。`QSD1` 返回帧按固定长度解析，不能依赖分隔标志在音频中唯一。
8. 搜索分页缓存为内存最多3页、8 MiB、120秒；只预取下一页。在线封面已有有限并发和磁盘缓存，默认128 MiB、2000文件、30天；图片缓存命中不证明歌曲已安装。
9. 本地下载识别按实际 Info 和谱面版本核验，使用有界扫描与继续扫描；记录中的同名、历史成功或缓存不能替代当前文件内容。
10. `.bplist` 以 hash 或合法 key 识别曲目，来源标题只用于显示；本地歌单与在线歌单分别保存/加载。整单下载沿用200个编号的批次上限。

2026-10-28 补充：本地歌单文件及来自 Quest 的清单可往返；歌单记录的读改写使用进程内锁，避免导入和在线保存相互覆盖。发现歌单使用与歌曲封面相同的四路缓存服务，接入磁盘缓存并避免在滚动中反复取消正在加载的图片。歌曲搜索与实际下载通过共享 `published_version` 选择同一可用发布版本；文字搜索格式错误与歌曲没有发布版本分别报告。

删除不会调用永久递归删除：本地使用 Qt 的 Windows 回收站接口，Quest 仅把已确认、Info 哈希仍一致的歌曲目录改名至当前根内新建的隐藏隔离区。新功能不自动清空隔离区。删除期间歌曲传输和设备歌单动作互斥，删除完成使曲库与下载识别快照失效后重读。
11. 设备区域通过“设备管理”接入无线设置，连接、配对和 USB 开启无线均由点击后发起，不保存配对码。`AdbBridge.run_result()` 为连接命令返回退出码、stdout、stderr；原 `run()` 的文本/二进制读取与传输契约未变。mDNS 解码支持经典、配对和 TLS 连接三类服务，目前为 IPv4；每次输出至多64KiB、至多128个发现端点，配对后寻找端口默认最多等待8秒，各命令另有超时。等待发现时不持有设备 I/O 锁，连接和身份核验仍通过共享 provider 序列化。进度仅发送带操作编号的普通消息，取消或关闭后忽略迟到结果；已发生的设备设置不会自动撤销。
12. 最近无线记录 `qt-wireless-recent.json` 为版本1，最多8台/16KiB，按硬件身份去重，仅存IPv4、端口、身份、型号；QSaveFile 原子写入，拒绝覆盖损坏、未来版本或符号链接文件。记录不证明在线，启动不自动探测。选中无线设备后，空闲且窗口可见时5秒一次有界检查，仅查看现有 transport 并核对身份；与媒体、读取、传输共用 provider 锁。出错即停检，旧快照保留但失效；由点击触发一次重连，不自动重试、传输或恢复快照可用。检查结果同时匹配请求代次、设备身份与读取代次，关闭/切换后丢弃。USB／无线通道归组尚未实施。
13. Python 文件使用 UTF-8 无 BOM；现有 `shell_*.ps1` 的 UTF-8 BOM 与 Windows PowerShell 5.1 中文兼容相关。控制台乱码不等于源文件损坏。
14. `LibraryWindow` 和 `DownloadWindow` 共用标题栏合并。品牌栏窄窗换行，原传输按钮移入顶部并保留回调/禁用/确认逻辑，日志紧随记录；窄窗日志显示图标。下载导航优先按完整宽度判断换行，必要时省略标签文字，避免滚动偏移遮住标签。窗口边缘与品牌区通过 Windows `WM_NCHITTEST` 交给系统缩放/拖动，最大化客户端按显示器工作区裁切；交互控件及 `QTabBar` 始终为客户区。窗口按钮使用普通Qt动作，未实现Windows 11最大化按钮悬停布局菜单。子弹窗保留各自标题栏。`WindowAppearance` 在显示/主题变更时请求DWM圆角/边框，不支持时仅在尺寸/状态变化裁切不透明圆角区域，最大化清除裁切。没有新增依赖、透明窗口、逐帧动画或Canvas重绘循环。
15. `SeekSlider` 共用0..1000绝对轴，鼠标按下/拖动期间保护滑块免受100ms播放轮询覆盖，释放只提交一次；键盘动作通过控件拥有的单次计时器等Qt传播数值后提交。主曲库总时长固定为整首音频时长，不再从当前播放偏移重建区间。暂停取消当前请求并保存绝对位置，续播用原引擎从该位置重新打开；不是音频引擎原生暂停。队列与详情选中项分离，播放所有权仍按请求编号核验，旧窗口不得停止新窗口的声音。网站试听保持原有最多30秒限制。
16. 日志沿用Qt独立运行目录的轮转`preview.log`，并接入`quest_tool.audio`的INFO及错误记录；查看日志不创建文件、不上传/清空日志。异步只读当前及两份轮转文件尾部，每份64KiB、界面2500行，展示/复制时替换常见敏感字段；不承诺识别所有敏感文本。原始日志内容及源歌曲不变。事务记录继续经过原`read_journals`校验、有界读取；新增筛选只隐藏展示项，不构造传输计划。
17. 在线歌单的`type=Search`允许`stats=null`及未知`total=None`，保留`dynamic`标记，列表不为统计数量额外抓取全部详情。普通歌单继续沿用原统计校验；编号、字段类型、官方链接、8MiB响应及每页500条的边界保留。详情首个短页可确认本次结果的真实数量；未知数量的满页继续分页，不能据此声明清单完整，后续短页也不伪造前页总数。`config.mapCount`不作为歌曲数量。只有完整、全部可解析、且去重后不超过200个编号的清单可整单入队；歌曲发布版本、下载解压和bplist保存沿用原服务，保存的是固定快照而非自动同步规则。

窗口实现参照 [Qt QWindow 的系统移动接口](https://doc.qt.io/qtforpython-6/PySide6/QtGui/QWindow.html) 和 [Windows WM_NCHITTEST](https://learn.microsoft.com/en-us/windows/win32/inputdev/wm-nchittest)；最大化工作区使用 [MINMAXINFO](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-minmaxinfo) 及客户端范围处理。接口依据与本机测试分别记录，不由文档存在推断物理多屏验收完成。

滑块事件顺序参照[Qt QAbstractSlider](https://doc.qt.io/qt-6.12/qabstractslider.html)；原生圆角使用[Windows DWM圆角偏好](https://learn.microsoft.com/windows/win32/api/dwmapi/ne-dwmapi-dwm_window_corner_preference)，原生属性调用成功不代替物理屏幕观感验收。

## Quest 歌单、音频与拖动入口（2026-10-28）

- `quest_tool/qt_ui/playlist_enrichment.py`：歌单显示层。按可见行批量读取官方 `/maps/hash/{hash}`（每次最多40个），核对精确版本哈希，复用四通道封面和有界磁盘缓存。原 `.bplist` 条目不被改写；未安装/暂不可获取的记录保留。侧栏没有内嵌封面时使用首首歌曲封面。
- `adb_playback.py` + `AdbReadOnlyProvider.read_playlist_index/read_audio`：只读 Quest 内容哈希索引及单首音频。绑定硬件、通道与根目录，验证 Info 指纹、路径/链接与读取前后状态；索引按小批次执行，兼顾 Windows 命令长度。此索引只用于查找，绝不写入 `LibraryIdentity.values`、代替传输核验或授予写权限。
- `library_audio_cache.py`：电脑隔离预览目录下最多两首、每首64MiB的临时音频；按设备/快照 epoch/文件夹/Info 指纹隔离。取消和关闭后回收自身缓存。`LibraryPreview` 沿用共享播放引擎与 request-id 所有权，设备或快照改变后旧播放失效。
- `audio._seekable_memory`：仅替换中段起播的定位方式。使用现有 miniaudio 公共 `StreamableSource`/`stream_any(seek_frame=...)`，避免逐帧解码丢弃前段，继续内存流式解码以兼容 Windows 临时文件移除。未增加依赖、未整曲转码。开始位置仍是绝对歌曲时间。
- `player_widgets.PlaylistPlayer`：主曲库播放器的第二个视图，同步状态、封面、音量、暂停、进度、上一首/下一首、随机与循环；不创建第二套音频所有权。歌单播放队列遵循当前歌单内同来源已安装歌曲的顺序。
- `library_drag.py`：应用内 Copy 手势。带一次性票据及固定曲库/设备 epoch，只将本次拖动的文件夹交给原传输确认窗口。拒绝外部、伪造、同侧和过期拖动；不支持任意文件拖入后直接推送。
- `LibraryPlaylists`/`WirelessForm` 复用 `LibraryHeader` 与 `WindowChrome`。歌单管理保留实例重开，设备弹窗关闭前释放窗口事件过滤；歌单新增固定播放栏后最小尺寸为700×520逻辑像素。`LibraryWireless.release` 与 `WirelessRecovery.browser_rendered` 保留正在交接的无线硬件身份，不把临时 USB 选择差异解释为无线断线。

协议依据：[BeatSaver 官方 API](https://api.beatsaver.com/docs/swagger.json)、[pyminiaudio 公共接口源码](https://github.com/irmen/pyminiaudio/blob/master/miniaudio.py)。本次同时检查了本机实际安装的接口签名，没有升级依赖。


当前Qt单文件打包使用 `packaging/quest_song_tool.spec`，独立入口 `packaging/entry.py` 复用当前界面/业务。构建与数据边界见 [单文件版与发布](单文件版与发布.md)。
