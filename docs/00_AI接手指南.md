## 1. 项目是什么

**Quest 歌单对比工具** —— Windows 桌面 GUI，用来对比 PC 本地与 Meta Quest 头显上的
Beat Saber 自定义歌曲（Custom Levels）。

| 项 | 内容 |
|---|---|
| 要解决的问题 | 玩家在 PC 上攒了一堆自制谱，往头显里拷的时候不知道**哪些已经有、哪些缺**，也不知道**重复了多少** |
| 三列视图 | 「本地歌曲」「Quest 歌曲」「缺失歌曲」并排；缺失列是**差集视图**，不是第三份曲库 |
| 核心操作 | 一键补齐缺失歌曲（本地→Quest）、反向补回、设备端删除、评分与评价、搜索排序、封面墙 |
| 附加功能 | 重复歌曲检测、歌单导入导出（`.bplist`）、试听片段、对比报告导出、无线调试、多语言（中/英） |
| 目标用户 | 自己动手拷谱的 Beat Saber 玩家（不是公开发行的商业软件） |

**这个工具会真的删掉用户头显里的文件。** 所有涉及写/删的改动都要格外保守 —— 见第 6 节。

## 4. 整体架构

### 4.1 分层

```
界面层     app.py / ui_*.py          只碰控件；所有 UI 更新都在主线程
任务层     workers.py                后台线程 + 消息队列 + 危险操作护栏 + PauseGate
数据访问   fsapi.py / device_*.py    统一成 SongFS 接口，屏蔽"本地盘符 vs Quest 设备"
功能层     audio.py / duplicates.py / playlist.py
持久层     database.py / storage.py  SQLite 缓存 + JSON 设置
基础层     songs.py / theme.py / messages.py / constants.py / logging_setup.py / diagnostics.py
```

### 4.2 关键设计（改代码前必须理解这 4 条）

**① `fsapi.SongFS` 抽象 —— 为什么必须有它**

Quest 走 MTP 时没有盘符，`os` / `shutil` 完全用不了。`SongFS` 把
「列歌曲 / 读 info.dat / 读封面 / 复制进出 / 删除 / 剩余空间」抽象成接口，
上层（扫描、对比、复制、删除）完全不关心底下是本地磁盘、adb 还是 MTP。
**新增任何设备通道，只要实现这个接口就行，上层一行不用改。**

**② 线程规约 —— 最容易踩的坑**

> **工作线程只允许 `queue.put()`，绝不允许碰 Tk 控件，也绝不允许调 `root.after()`。**

原版有 11 处违反这条，负载高时随机崩溃。现在所有后台任务经
`workers.TaskRunner.submit()` 提交，用 `TaskRunner.emit(kind, text, percent, payload, token)` 发消息，
主线程 `_pump_queue()` 消费后更新界面。
`tests/static_check.py` 第 4 项会自动检查这条（扫所有 `tasks.submit(<名字>)` 的函数体）。

**③ 「缺失」是视图，不是曲库**

`app.libraries` 只有 `local` 和 `quest` 两项。第三列的歌曲**真正属于** `missing_side` 指的那一侧
（`missing_side == "quest"` 表示"Quest 缺的"，即歌在**本地**）。
所以任何要"拿到这首歌的真实库"的地方都必须经过 `app_report._sample_kind()` / `app_delete._real_kind()` 映射。
**直接写 `self.libraries["missing"]` 必然 `KeyError`** —— v17.7 真踩过，而且因为它在按钮回调里，
异常被 Tk 吞掉，表现成"点了没反应"。

**④ 两条铁律**

* **mixin 不能反向 import `app.py`**（循环依赖）。共用小工具放 `app_common.py`。
* **所有用户可见文字都走 `messages.tr()`**，中英两份必须键一致、占位符一致。

## 8. AI 开发规范

### 8.1 三条铁律

1. **文档里不许写没验证过的结论。** 凡是"已完成 / 已修复 / 实测通过"，必须有命令输出或数字支撑。
   本项目最高发的缺陷是**「写了但没生效」**（累计 12 次）—— **文档会替错误打掩护**。
2. **改完代码立刻跑 `python tests\static_check.py`**（7 项，秒级）。
3. **功能不许丢。** 这个工具会真删用户文件；任何改动先问"会不会让它删错东西"。

### 8.4 常见陷阱（速查，完整 55 条见 `03_踩坑记录.md`）

| 陷阱 | 记住什么 |
|---|---|
| 编辑工具会静默去掉 `.ps1` 的 UTF-8 BOM | 静态检查第 2 项守着，改完必跑 |
| 用 `Set-Content -Encoding UTF8` 改 `.py` | Windows PowerShell 5.1 会写入 BOM → `ast.parse` 报 `invalid non-printable character U+FEFF` |
| 按钮/`after` 回调里的异常被 Tk 吞掉 | 表现为"点了没反应"，不是报错；必定是 `AttributeError` / `KeyError` |

| `Select-Object -Last` 会缓冲到进程结束 | 想看进度要重定向到文件 |
| `python -c` 内嵌中文/引号极易炸 | 写成脚本文件再跑 |
