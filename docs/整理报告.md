### 3.1 死代码复查

方法：AST 统计全仓 **661** 个函数定义，与「被使用的名字」求差。

**`ImportFrom`/`Import` 的导入名（含别名）**、字符串字面量。

**删除 5 个零调用函数**：

|---|---|---|
| `_pause_on_error` | `main.py` | `main.py` 只有 `raise SystemExit(main())`；三个启动器各有自己的错误处理（`启动.bat` 用 `start` 不等待 + 三段 `pause`；`启动.pyw` 有 `MessageBoxW`；`启动.vbs` 用隐藏 `shell.Run` + MsgBox） |

### 3.3 ★ 本轮最值得记的教训：删掉了活代码

第一轮把 `audio.find_file` 判为死代码删掉。**它是活的** —— `app_detail.py` 用别名导入引用：

```python
from .audio import find_file as audio_find_file   # 扫描器看不见这一行
...
path = audio_find_file(folder)                    # app_detail.py:490
```

**为什么会漏判**：扫描器只收集「调用名 + 变量/属性引用 + 字符串字面量」，
**不收集 `ImportFrom` / `Import` 的导入名**，于是别名导入（`as audio_find_audio_file` 之类）完全看不见。

**怎么暴露的**：**跑测试**。静态检查 7 项**全部通过** —— 它只做 AST 判断、不真的 import 模块：

```
File "quest_tool/app_detail.py", line 13, in <module>
    from .audio import find_file as audio_find_file
ImportError: cannot import name 'find_file' from 'quest_tool.audio'
```

**修法**：让 `app_detail` 直接导入真实实现，不再经过那个别名：

```python
from .audio import _find_audio_file as audio_find_audio_file
```

**改进**：扫描器补上 `ImportFrom`/`Import` 的名字收集后重跑，确认零死代码。

**教训（已写入 `docs/03_踩坑记录.md`）**：

1. **「零调用」的判据必须包含别名导入**，否则删的是活代码；
2. **这类错误静态检查抓不到** —— 静态检查再全也看不见运行时的导入错误，
   **必须真跑测试**才能兜住；
3. 删任何东西之前，先在**全仓 grep 该名字**（含 `import ... as`），再动手。
