## 拆批依据与范围

用户继续M7B2。源码审阅发现AdbFS.copy_into会先remove_tree同名目标，中文暂存还会调用旧storage.data_dir；copy_out也会移除传入的local_dst后os.replace。不能把这些API直接接到新版用户目录并声称非覆盖安全。因此本批先实现Quest→本地，向Quest推送/覆盖备份/删除留后续；没有修改旧后端或绕过其护栏。旧回归验证不等于新版真机验收。

新增transfer_pull.AdbPullBackend：固定计划只允许to_local和Windows；每首复核显式ADB序列号、硬件序列号、Quest型号/代号/品牌、根白名单和规范路径。只使用devices/getprop/root检查、find、目录检查及pull，不使用push/mkdir/mv/rm等设备写命令。源目录及其子树拒绝链接；本地拉取结果拒绝符号链接/目录联接与越界。不存在默认后端或导入时自动I/O。

拉取使用目标根下新建的.quest-pull-*独立目录，旧AdbFS.copy_out仅操作其私有payload与.partial，不传入最终用户目录。拉取前后比较原文件数/总字节，复用verify_copy并要求Info文件存在；不宣称内容哈希校验或全谱面语义校验。复核身份/本地根后用Windows os.rename发布；该平台若目标已存在则报错，避免os.replace覆盖。已有目标在队列阶段跳过；若目标在传输中出现，阻止发布并保留后来目标。清理只处理本批新建且父根/节点身份仍一致的暂存；若根或暂存被替换则不删未知路径，可能留下待人工处理的暂存。

## 界面与用法

LibraryTransfer在显式启用时提供Quest可见歌曲勾选、清空、导入勾选到本地、导入勾选的本地缺失。缺失视图必须origin=quest，不能反向把本地缺失解释成向Quest写入。只处理已载入且无读取错误的被勾选行，不自动全选或导入。默认曲库/只读ADB启动方式仍不开放导入。

```powershell
cd "D:\AIHarness\P006_Quest3Bs歌曲转移"
python main_qt.py --library --quest-adb --quest-pull
```

这条命令只启用入口，不自动发现、读取或复制；仍须选本地目标、手动刷新/选择设备/读取快照、勾选，再在任务窗口核对设备和两端路径并点击“确认并导入”。UI读取快照仍是整目录，不是受限8首采样。不要将该启动方式当成M7A2F目录缺失的修复。本批没有实际执行这条真实设备启动流程。

TransferDialog默认保留M7B1模拟模式；实际导入显示独立文案，开始前再核对当前就绪身份/目标。切目录、清快照和关窗取消后续任务；当前在途歌曲允许完成。任务结束仅对仍匹配的本地目标刷新；关闭任务窗但主窗仍开时，后台收尾结果同样驱动匹配刷新，主窗关闭后不更新GUI。后台只发消息，Qt主线程安装结果；删除窗口和已结束队列可释放，防止连续任务保留所有历史窗口。
