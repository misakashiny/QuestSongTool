# Quest 资料优先加载与封面信息

本批针对“Quest 读取仍慢、封面和 BPM 不显示”。先返回已完成设备身份与目录复核的歌曲资料，再补当前可见及详情选中歌曲的封面、缺失时长。未改变搜索、下载、试听引擎、数据库结构或设备传输/删除实现。

## 1. 已核实原因

1. 原 `AdbReadOnlyProvider.read_library()` 对每首缺失时长的歌曲读取音频头尾，完成全部歌曲后才返回列表。上批已将单曲往返由三次合并为一次，但首屏仍等待整批时长。
2. `DetailPanel.select()` 原来用 `dict(row, bpm=0, difficulties=(), ...)` 构造详情，覆盖了 Quest 快照已有的 BPM、难度。远端条目不走本地详情读取，因此一直显示未知。
3. 原 Quest 快照没有传递封面文件名，列表绘制只连接本地封面缓存；远端列表和详情缺少封面读取链。

## 2. 实现范围

- Qt 设备页面请求 `metadata_only`；只有同时提供 `read_metadata` 与 `read_assets` 的 provider 才启用分阶段模式，其余 provider 走原 `read_library`。直接调用 `read_library()` 的默认时长读取及旧 CLI 保持。
- 首阶段仍完成原目录枚举、Info 读取、设备身份/根目录结束复核；保留 `skipped_names` 和不完整快照护栏。音频/封面不参与首阶段。元数据带上已有 BPM、难度，以及副标题、格式版本、受校验封面名、Info SHA-256。
- 详情使用“默认值后由已有资料覆盖”。Quest 行副标题显示作者与 BPM；详情展示 BPM、难度、格式版本和已有副标题。
- 新媒体 presenter 使用原 SearchSession 单消费者；80ms 合并调度，单批最多4首，优先详情选中项，其次 Quest 和“本地缺失”列表实际可见项；每表最多检查64个候选索引。不会自动轮询整库。
- 同一个 ADB provider 的枚举、资料与媒体操作共享可取消 I/O 锁。单个命令仍最多10秒，媒体批次最多45秒。后台只处理普通数据及 Pillow 图片，Qt 控件和 pixmap 在主线程更新。
- 每批媒体前后核验设备/硬件身份和根目录；每首重读 Info，SHA-256 不匹配即停止该项并提示重读。封面仅允许歌曲直接文件、拒绝链接、检查规范根、单张最多5MiB、尺寸最多4096×4096，再转256×256 RGB PNG。时长复用既有受限音频头尾解析，不读取完整音频、不播放。
- 图片复用现有128张/32MiB源图缓存和128张/16MiB缩放缓存；额外 PNG 字节最多128张/16MiB，尝试记录最多256项。清空/取消/重读/换设备根后清缓存，迟到结果按代次/身份丢弃；淘汰后重访可重读，无图/失败项不自动反复请求。
- 时长补全只发 `dataChanged`；Quest及缺失代理关闭自动重排，避免“未知时长排前→补全后移走→下一批未知进入视口→读完整库”。点击表头仍可按当前时长重排，搜索/分类主动过滤，本地评分排序保持。
- 保留当前勾选、当前行、滚动位置、快照时间。明确设备失联/身份变化沿用原失效链清除快照。
