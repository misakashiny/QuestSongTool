# Qt本地下载记录核验

时间：2026-10-23T23:30:43+08:00。本批已实施并通过必要验证；完整产品与音频集中验收继续暂缓。

## 范围与用户行为

当前范围是“下载记录对应路径”的核验，不是全库扫描。新版下载窗口启用下载协调器后，自动核验当前保存目录中done/exists记录的installed路径；终态记录集合、路径、哈希或目标变化时清除旧结果并重验。选项菜单新增“重新核验本地下载记录”，现有链接/ZIP页本地刷新也会触发；忙时菜单禁用。结果只在内存中保存，重开重新检查，不写数据库或修改任务历史。文件在外部变化不会自动监视，最近核验时间在菜单/详情提示中显示，用户可手动重验。

| 状态 | 依据 |
| --- | --- |
| 本地同版本 · 已核验 | 实际结构有效且谱面哈希与当前在线歌曲哈希相同 |
| 本地其他版本 · 已核验 | 同一在线编号的记录路径实际哈希仍匹配该历史版本，但不同于当前在线版本 |
| 记录对应目录已缺失 | 记录的合法直接子路径不存在；不等于全库没有这首歌 |
| 本地版本与记录不符 | 结构有效，实际谱面哈希与该记录不同 |
| 本地记录未能核验 | 文件不完整、读取/权限错误、越界/链接、读取时变化、预算限制等 |
| 同/其他版本下载记录 | 尚未核验或无installed路径的历史信息，明确不表示当前已安装 |

活动队列状态优先；核验通过的相同哈希可跨编号/ZIP记录识别精确版本。其他版本只沿用在线编号对应关系，不凭同名歌曲归类。无记录手动导入歌曲、被重命名/移到别处的目录不自动搜寻；记录路径缺失不会误称全库缺歌，也不禁止下载。原DownloadManager去重/结构校验继续决定实际下载行为。

## 实现与护栏

复用SearchSession单消费者后台任务、取消事件和消息回传，250ms合并请求，40ms主线程轮询。工作只接普通数据，不触碰Qt；主线程只处理菜单和状态。切换目录、更新记录或手动重验立即清空已核验标签、取消旧代次；代次或目标不符的结果不更新界面。关闭窗口不等待慢读取，退出前协调器保留并等待已有工作结束，继续保护运行锁。

历史不是任意路径读取授权：只读当前目标直接子目录；词法与规范化父子关系均核对，目标祖先、歌曲目录和遍历子项拒绝symlink/junction。每个歌曲前后结构指纹包含路径/大小/修改时间/文件标识，读取变化标为未知。此为普通外部变更检测，不是抗恶意并发文件替换保证；同大小/同时间戳的刻意改动或读完后变化不保证检测。

调用原validate_song检查info、所需谱面/音频等文件存在与基本结构，并复用原song_hash（Info.dat和难度文件原始字节）；不会播放或读取音频PCM，不提供音频/封面完整内容校验，也不改共享解析器。读取边界：最多前512条候选记录，同一路径单批去重；每首最多512个树项、256个难度文件、Info.dat 2MiB、单难度16MiB、单首预留读取32MiB、每批预留读取256MiB。预算不足或异常标未知而非已安装/缺失；哈希前后保留取消点，底层单次文件读取不能强行即时中断。未添加文件写入、自动修复/覆盖/删除、下载限制或设备动作。
